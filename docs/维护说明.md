# 维护说明

## 新 Codex 对话如何接手

打开同一项目 `E:\Codex_Projects\简历网申投递助手`。先读根目录 `AGENTS.md`，再读 `memory/PROJECT.md`、`memory/STATUS.md`，按当前任务读取 `memory/DECISIONS.md` 和一两份相关会话文件。核对 `git status --short --branch` 与实际代码；不用读所有历史对话。最新用户指令优先。

项目开发记忆和插件个人资料库相互分离。禁止把真实简历、联系方式、证件、登录态、Cookie、密钥或用户原始聊天写入开发记忆。不要扫描相邻“2026秋招”或其他项目。默认串行维护；并行时写明文件范围并用分支 / worktree，合并后更新统一状态，不能假定不同 worktree 实时同步。

## 架构和命令

| 路径 | 职责 |
| --- | --- |
| src/ui | 可信侧栏 / 选项页，资料编辑、导入差异、预览、最小字段批次 |
| src/core/model.ts | schemaVersion=1、字段注册表、稳定记录ID、来源、确认、验证 |
| src/core/matching.ts | 精确中英映射、上下文冲突、日期和选项格式、填写计划 |
| src/core/storage.ts | 本地资料和规则、可信访问范围、revision 与写锁 |
| src/parsers | 本地 PDF.js/Mammoth、保守文本标签解析 |
| src/background | action/侧栏、activeTab 注入、来源与状态校验；无完整资料库传输 |
| src/content | DOM 标签/分组/控件描述、原生写入事件、有限核验与撤销 |
| src/adapters | 通用适配器接口；当前没有实测招聘站专属适配器 |
| tests | 虚构测试原件、单元测试、真扩展 E2E |
| scripts | 构建、维护入口、产物审计、测试页服务器、checkpoint/Hook |
| dist/extension | 唯一稳定加载目录，生成内容，不手工编辑 |
| artifacts | 最近一次报告、截图、上一构建备份、测试浏览器；不打包进扩展 |

用本机 Node.js 22+。当前检测到 Node 24.19.0 与 pnpm 11.19.0，npm 不在 PATH。入口会查找 PATH 中 pnpm 和本机 Codex 捆绑的已知回退位置，不下载新运行时、不改全局配置。

```powershell
node scripts/workspace.mjs install
node scripts/workspace.mjs check
node scripts/workspace.mjs e2e
```

日常源码改动：双击 `一键构建.cmd`。失败会显示错误，返回非零；不会静默宣称成功。安装依赖遵守 pnpm-lock.yaml；esbuild 构建脚本在项目 pnpm-workspace.yaml 明确允许，其他依赖没有一揽子脚本授权。pnpm 11 的 storeDir 等设置放 workspace YAML，非 registry 设置不依赖 .npmrc。缓存仅在项目 .pnpm-store 内，测试 Chromium 在 artifacts/playwright-browsers 内。

定向测试可使用原生 Node 入口，避免 Windows cmd 包管理器包装层把正则 `|` 解释为管道：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) 'artifacts\playwright-browsers'
node node_modules/@playwright/test/cli.js test --grep '多经历|后台'
```

新增依赖前核对官方文档、授权和变更。更新锁文件后跑相应回归；不要自动全量升级。构建仅打包业务代码、解析依赖、资源、manifest 和许可证。`src/extension-key.json` 是生成的**公开**身份键，无私钥；不要替换，否则扩展身份可能变化。

## 给出新岗位链接后怎样适配

1. 用户提供实际链接并完成登录 / 授权。没有实际可访问页面时记录“待验证”，不要根据平台名称声称支持。
2. 在用户允许的当前页面只读扫描，检查字段 label/aria/placeholder、分组、重复经历、选项和动态变化。不要复制完整 DOM、已填值或登录态到测试与记忆。
3. 优先修正通用识别中的可验证问题。特殊站点逻辑放 src/adapters，以精确来源和经过验证的结构为条件，不把个人值硬编码。
4. 为最小结构创建脱敏虚构 fixture，覆盖正常路径和同名冲突、空值、已有值、重扫、回退与页面变化。增加实际加载扩展的 E2E，而不只调用网页函数。
5. 执行 check 和相应 E2E；需要时在授权真实页面做扫描 / 预览和用户确认后的填写核验，不自动提交。不同浏览器分别记录结果。
6. 构建 → 扩展管理页重新加载 → 当前表单刷新 / 重新扫描。更新参考依据、测试报告、STATUS 与会话 checkpoint。

对于 iframe、封闭 Shadow DOM、省市级联、搜索学校和自定义日期，第一版走人工复制和真实选项选择。下一版只有在可明确验证选项和值、可处理回退时才增加自动化。新增经历按钮仍未实现；若以后实现，必须用户确认、单站点验证、去重与回归。AI 后续单独设计默认关闭、发送预览、脱敏字段名白名单和输出校验，不能获得脚本执行或提交能力。

## 开发记忆怎样更新

每个环境检查、选型、功能、问题修复、测试 / 构建、重要配置完成后立即运行：

```powershell
node scripts/checkpoint.mjs --step '步骤名' --result success --summary '实际做了什么及证据，不含个人值' --files 'src/core/matching.ts tests/unit/core.test.ts' --next '下一步具体操作'
```

result 只能为 success / failure / pending / observed。代码已写但未测用 pending；失败必须 failure；Hook 事件只能 observed。退出码不能替代业务验证。脚本通过文件锁、临时文件原子改名、事件ID去重和有界尾部日志写入；竞争 / 过期锁或写失败会明确报错。不要任意删除锁；先确认没有其他写入进程，再处理残留。

`STATUS.md` 保留简短长期当前状态，脚本只替换末尾最近 checkpoint 区域。重要阶段变化仍须由维护者更新正文，避免旧状态与最新 checkpoint 冲突。sessions 每天每会话单独文件，约 65 KB 后裁剪早期尾外事件；持久结论保留在 STATUS / DECISIONS。脚本不保存完整输入输出或聊天、不调用 Codex。

## Hooks：已配置，尚未由用户信任

本机 Codex CLI 0.153.1 的 features 显示 hooks stable=true；已核对官方文档及本项目 `.codex/hooks.json` 和 `.codex/config.toml`。

- SessionStart：提示上述读取顺序。
- PostToolUse：仅匹配 Bash（官方包含 exec_command）、apply_patch / Edit / Write，记录脱敏事件和有限 Git 文件名；未知结果保留未知。
- Stop：检查 STATUS 是否近期更新且包含下一步，提醒人工核对交接，不自动宣布业务成功，也不自动阻塞或调用模型。
- 调研 / 设计、托管网页搜索和未覆盖工具用语义 checkpoint 补充。

**本次仅测试了合成 Hook 输入，未观察到真实 Codex Hook 触发。** 当前实际覆盖是 AGENTS 工作流程 + 维护者逐步 checkpoint + 构建/维护脚本自动记录结果。

启用方法：在本项目开启新的 Codex CLI 会话（若本机 app 不提供 Hook 审阅入口，使用 CLI），在 CLI 输入 `/hooks`，找到项目 `.codex/hooks.json` 的三项定义，检查它们只调用本项目的 scripts/hooks.mjs，并信任。项目 `.codex/` 层也需是受信任项目；按客户端显示的信任提示正常处理。不要使用任何跳过信任的参数。当前命令依赖此 Codex 会话中的 `node` 可用；如果报找不到 Node，可让维护者把命令换成本机已确认的 node.exe 绝对路径，再重新审阅信任。

Hooks 按定义 hash 信任，修改后必须重新审阅。要验证 SessionStart，应在信任完成后再新建 / 重启会话；运行一个无敏感输出的检查，再查看 sessions 是否出现 **真实** Hook SessionStart / PostToolUse。确认停止时出现 Stop 提醒后，才更新 STATUS 的自动化覆盖。不要为验证而启动 Codex 自我套娃写总结。

官方来源：[Hooks 与信任规则](https://developers.openai.com/codex/hooks)、[AGENTS.md 发现顺序](https://developers.openai.com/codex/agent-configuration/agents-md)。

## 备份、数据结构和目录清理

重要旧成果破坏性修改前先备份并读取验证。构建会将上一版 dist/extension 复制到 artifacts/previous-extension，并逐文件 SHA-256 核对，再替换加载目录。只保留上一版，不无限累积。测试结束会清理本次 UUID 隔离浏览器用户目录；报告目录重复运行覆盖。不要删除未知文件，尤其 data/private 中由用户放入的原件。

浏览器库与 data/private 不自动同步；升级前导出备份，不卸载。schemaVersion 变化需显式迁移函数、旧备份回归、稳定 ID 保留和失败不覆盖测试。当前不支持其他版本，以拒绝导入保留旧库为策略。

2026-09-05 用户明确授权上传本工程到私有仓库 [Liiiin-hku/resume-application-assistant](https://github.com/Liiiin-hku/resume-application-assistant)，替代初始仅本地 Git 的约束。提交前检查忽略规则和 staging 清单，只提交源码、锁文件、虚构 fixtures、必要文档与脱敏项目记忆。dist、私有数据、凭据、缓存、测试用户目录、截图和个人导出文件不提交。不强推、不操作其他仓库；修改可见性或向其他目的地上传需要新的用户要求。

## GitHub 后续更新

先核对 `git remote -v` 指向上述仓库、`git status --short --branch` 和最新记忆。如果本地干净且有远程更新，使用 `git pull --ff-only`；出现分叉就先检查，不使用 reset / force 覆盖。完成修改、适当测试、构建和记忆更新后，在用户要求上传时审查暂存文件，执行 `node scripts/publish-audit.mjs`，再提交并 `git push origin main`。只改开发文档无需重复整套浏览器测试。

发布新的可安装版本时，更新 package.json 中版本号并重新构建。执行 `./scripts/package-release.ps1`，生成 `artifacts/releases/v版本号/` 下的 ZIP 与 SHA256SUMS.txt。脚本先运行产物审计，再逐条校验 ZIP 文件与构建内容；同版本已有包不会静默替换。不要更改全局执行策略。

在 GitHub Releases 创建与已推送提交对应的版本标签，上传上述两个文件，并说明本轮实际测试和限制。发布前核对仓库仍为私有。可以用 GitHub 网页或已授权 CLI 操作；凭据只交给官方登录流程，不记录到仓库或项目记忆。仓库源代码与插件内的资料存储彼此独立；推送源码不等于备份个人简历资料。

附加验收入口：`node scripts/edge-smoke.mjs` 使用本机 Edge 的隔离资料目录和 CDP 加载测试，不读取日常浏览器资料；`node scripts/handoff-check.mjs` 在新 Node 进程验证交接读取顺序、当前版本和下一步。这些均不等同于人工安装或真实 Codex Hook 触发。Windows `.cmd` 文件必须保持 UTF-8、CRLF；.gitattributes 已固定行尾，避免中文命令被 cmd 错误分行。
